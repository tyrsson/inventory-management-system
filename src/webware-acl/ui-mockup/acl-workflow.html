How should access be granted?

An inherited grant is set on an ancestor role and flows down to all descendant roles. An explicit grant targets exactly one role and does not propagate.

Inherited
Set on a parent role. All child roles gain access automatically.
Explicit
Targets exactly one role. Does not propagate to child roles.

Assertion optional

An assertion adds a runtime condition. The ACL check passes only when the role/resource/privilege match and the assertion returns true. Select None to skip.

None
No assertion. The rule grants or denies access based solely on role, resource, and privilege.
OwnershipAssertion
Passes only when the authenticated user's ID matches the resource owner's user ID. Use for "edit own record" scenarios.
StoreOwnedResourceAssertion
Passes only when the resource belongs to the same store as the user's active store. Use for store-scoped data.
