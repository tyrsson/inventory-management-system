## Session Accomplishments

### Root cause fix — acl.global.php not written

- **`config/config.php`**: Added `Webware\ConfigManager\ConfigProvider::class` to the
  aggregator. This was the root cause of the silent write failure — `ConfigSaveListener`
  was never registered in the event dispatcher so `ConfigSaveEvent` dispatched to zero
  listeners. Rules now write correctly to `config/autoload/acl.global.php`.

### `ConfigSaveEvent` — replace flag

- Added `public readonly bool $replace = false` as a final constructor parameter.
- **`ConfigSaveListener`**: when `$event->replace === true`, uses a single `ArrayProvider`
  with the full new config (bypasses the additive-only merge). When `false`, merges delta
  on top of existing config as before.

### `UpdateRuleTypeCommand` / `UpdateRuleTypeHandler` — fully implemented

- **`UpdateRuleTypeCommand`**: signature changed from `(int $id, string $type)` to
  `(string $roleId, string $resourceId, string $newType)`.
- **`UpdateRuleTypeHandler`**: full read-modify-write with one-level cascade:
  1. Reads full ACL config
  2. Preserves assertions from old rule entry
  3. Removes old rule (`unset`)
  4. Adds new rule under `$newType`
  5. Finds direct children of `$roleId` (where parent appears in their parents list)
  6. For each direct child with no explicit rule on this resource, writes an explicit
     `$oldType` rule so their effective access is preserved
  7. Dispatches `ConfigSaveEvent` with `replace: true` carrying the full modified config
- **`UpdateRuleTypeHandlerFactory`**: now injects `EventDispatcherInterface` alongside config.
- **`ProcessRuleMiddleware::processPatch`**: removed integer `$id` approach; reads `role_id`,
  `route_name`, `type` from request body. Dispatches `UpdateRuleTypeCommand`.

## Key Design Decisions

- Rules are config-only (`allow`/`deny` in `acl.global.php`) — no DB rule rows
- `UpdateRuleTypeHandler` cascades only one level (direct children); grandchildren inherit
  naturally from their updated parent
- `replace: true` on `ConfigSaveEvent` bypasses additive merge for full-config rewrites
- `RuleManagerHandler` / standalone Rules page: eliminated — the Access Control overview
  is the single UI for rule management
- No inline styles in templates — all custom CSS goes in `public/assets/css/custom.css`
- `webware-usermanager`/`webware-acl` stay clean — no `ims-store` dependency
