### `RuleFilter` rewrite needed
Current `RuleFilter` is `final readonly class` but assigns properties inside `filter()` —
this will throw at runtime. Needs redesign. Agreed convention:

```php
final class RuleFilter
{
    public readonly string $roleId;
    // ...
    private bool $valid = false;

    private function __construct(array $body) { /* assign + validate */ }

    public static function fromRequest(ServerRequestInterface $request): self
    {
        return new self((array) $request->getParsedBody());
    }

    public function isValid(): bool { return $this->valid; }

    public function getValues(): array { /* keyed to command param names */ }
}
```

Middleware pattern going forward:
```php
$filter = RuleFilter::fromRequest($request);
if (! $filter->isValid()) {
    return $handler->handle($request);
}
$result = $this->commandBus->handle(new SaveRuleCommand(...$filter->getValues()));
```

### `webware-filter` package (design agreed, not started)
- Owns `InputFilterInterface` mirroring Laminas `InputFilterInterface` signatures
- `setData() / isValid() / getValues() / getMessages()`
- Independent now; swap for Laminas when service-manager v4 compatible releases land
- `toArgs()` / mapping concern: NOT on the interface — input names keyed to command param names
  by convention so `getValues()` is directly spreadable
